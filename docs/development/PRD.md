## 1. 背景与问题

### 1.1 现状痛点

公司 ERP（Genero GDC / Tiptop 风格，AIX 主机）日常数据提取传统上依赖两条路径：

1. **图形客户端手工操作**：打开 GDC → 逐屏导航 → 手工抄录。慢、易错、无法自动化，且占用人工。
2. **直连数据库查询**：绕过应用层，存在口径偏差与安全合规风险，且无法执行需要走业务校验的写操作。

同时，团队正在引入 AI agent（WorkBuddy 等）承担日常数据工作（订单跟踪、新单复刻、物料齐套分析），agent 需要一个**结构化、可校验、可自动化**的 ERP 访问入口。

### 1.2 产品定位

erp-sim 是一个**面向 AI agent 的 ERP 协议 CLI**：以一次调用一份 JSON 请求的契约，封装 ERP 的 Telnet/DCP 协议交互（登录、导航、翻页、登出），让 agent 和脚本用统一、可校验的方式读取 ERP 数据、执行受控写操作。

**一句话**：把"人点 GDC 屏幕"变成"机器发 JSON"，且每次调用自带完整性校验与审计信息。

### 1.3 竞品/替代方案边界

| 方案 | 优势 | 劣势 | 本产品立场 |
| --- | --- | --- | --- |
| GDC 手工操作 | 全功能 | 无法自动化 | 替代其高频查询场景 |
| 直连数据库（如 JNOkr_LEXY2025） | 快 | 绕过业务口径、无写校验 | 并存；口径以 ERP 为准 |
| RPA 模拟键鼠 | 不碰协议 | 脆弱、依赖 GUI 会话 | 不采用 |

## 2. 目标与非目标

### 2.1 目标

- **G1 结构化契约**：所有输入输出均为带版本号的 JSON，agent 无需解析人类可读屏幕文本。
- **G2 可校验的完整性**：每份响应自带 `ok` / `complete` / 行数核对 / `logout_verified`，调用方可机器判定结果可信度。
- **G3 零依赖便携**：无第三方运行时依赖，`uv tool install` 一条命令全局部署。
- **G4 最小权限与显式确认**：读操作与写操作分级；写操作强制 `confirm_write=true`，绝不自动重试。
- **G5 Agent 技能分发**：随包维护渐进式披露的 SKILL.md，安装 CLI 的同时获得用法知识。

### 2.2 非目标（当前版本明确不做）

- 通用 ERP 业务动作执行引擎（任意画面任意键序）。
- 交付日期、客户、状态、厂区等更多查询过滤维度（协议画面未开放）。
- 压缩 DCP 传输、断点续传。
- 跨 ERP 系统的通用抽象层。
- 图形界面或 Web 服务形态。

## 3. 用户与场景

### 3.1 目标用户

| 用户 | 描述 | 典型诉求 |
| --- | --- | --- |
| **AI agent（主用户）** | WorkBuddy 等自动化助手，每日定时任务与按需查询 | JSON 进 JSON 出、退出码判定、无人工介入 |
| 工艺/计划工程师 | 小迪及同事，电机一厂/二厂订单与物料跟踪 | 快速拿到订单/物料/BOM 明细，导出表格 |
| 自动化脚本 | 定时任务（如每日 10:00 新单复刻链路） | 稳定契约、原子输出文件、可审计 |

### 3.2 核心用户故事

1. 作为 agent，我要按订单号模式+日期区间拉取全部销售订单明细（自动翻页），以便和陈芳的《N日ERP新单》邮件对账。
2. 作为工程师，我要查某个成品 BOM 的全部分层结构（文本报表落盘），以便核算齐套缺口。
3. 作为 agent，我要查指定料件的**受订量（aimq131）/ 库存量（aimq102）/ 在制量（aimq136）**三件套，以便生成物料齐套分析。
4. 作为工程师，我要在显式确认后**创建一张生产工单**（asfi301），拿到 ERP 分配的完整工单号，全程留痕不自动重试。
5. 作为定时任务，我要把查询结果原子写入 JSON 文件并校验登出成功，失败时保留旧文件不覆盖。

## 4. 功能需求

### 4.1 功能总览（v0.11 已交付）

| # | ERP 程序 | 功能 | 访问类型 | 版本历程 |
| --- | --- | --- | --- | --- |
| F1 | cxmr4103 | 销售订单查询（模式+日期区间，自动翻页） | 读 | 0.2 首发 |
| F2 | abmr001 | 产品结构表 BOM 查询（主件展开，文本报表） | 读 | 0.5 |
| F3 | aimq131 | 料件订单受订量明细（精确料号） | 读 | 0.9 |
| F4 | aimq102 | 料件数量明细-动态资料（含分仓库存） | 读 | 0.10 |
| F5 | aimq136 | 料件在制量明细 | 读 | 0.11 |
| F6 | asfi301 | 生产工单创建（单张，显式确认） | **写** | 0.9 |

### 4.2 传输与契约（核心平台能力）

- **单一 JSON 请求**：`erp-sim --request file.json` / 单 JSON 参数 / stdin（`-`）。输入上限 65,536 字节 UTF-8；未知字段、重复键、非有限数、非法 Unicode、不支持的版本一律在连 ERP 前拒绝。
- **单一 JSON 响应**：stdout 恰好一份文档；日志走 stderr；仅 `--help` 人类可读。
- **版本化契约**：`request_version=1`，查询响应 `response_version=2`，发现元数据 `schema_version=3`，请求错误 `version=1`——各自独立演进。
- **离线发现命令**（免凭证免网络）：`features` / `capabilities` / `version` / `schema`（含各功能响应 schema 与请求错误 schema）。agent 先发现、后调用，不猜接口。

### 4.3 连接与配置

- 凭据与配置四级优先级：**JSON 请求 > `ERP_SIM_*` 环境变量 > 显式 TOML > 默认值**。
- 敏感项策略：密码仅走请求/环境变量（TOML 拒收密码键）；hostname 为向 ERP 上报的客户端身份（多工作站环境必须显式指定）；凭据、客户端身份、报表 URL 永不进入公开响应。
- 回调监听：ERP 服务器需能反连客户端 IPv4 监听端口（默认 6401，可配 6400..6500）；并发会话需不同端口。
- 会话模型：一次调用一个会话（登录→操作→登出），`logout_verified` 为强校验项。

### 4.4 输出与失败处理

- `output` 字段可将 stdout 同份 JSON **原子落盘**（失败保留既有目标文件）；请求文件/TOML 不得同时作为输出目标。
- 退出码枚举（节选）：0 成功 / 2 参数无效 / 3 配置错误 / 4 认证失败 / 6 超时 / 9 结果不完整 / 10 登出未验证 / 11 端口占用。
- **确定性重试策略由调用方负责**：认证不确定、部分结果、登出未验证后禁止自动重试（尤其写操作）。
- 超时预算建议：查询 ≥ `timeout + cleanup_timeout + 25`s（默认 195s）；abmr001 另加报表下载 20s。

### 4.5 写操作安全设计（asfi301）

- 请求必须显式携带 `confirm_write=true` 才会提交。
- 单请求单工单，返回 ERP 分配的完整工单号；支持多行备注。
- `automatic_retry: false`：响应不确定时，调用方必须先核对 ERP 实际状态再决定下一步。
- 部门守卫（`expected_manufacturing_department`）可选启用，防止开错组织。

### 4.6 Agent 技能分发

- 仓库维护 `.agents/skills/erp-sim/`（SKILL.md + references/ + agents/），随 wheel 打包。
- 安装约定：CLI 与 skill **同版本同步部署**（备份旧版 → 复制新版 → diff 校验），技能内含连接设置、各功能查询构造、结果解读、失败处置四类按需加载参考。

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 兼容性 | Python ≥3.12；Windows（Git Bash/PowerShell）/程序化调用；无第三方运行时依赖 |
| 性能 | 单会话查询默认预算 150s+20s；翻页自动；无并发内部状态 |
| 可靠性 | 原子写输出；DCP 分片等待（0.9 修复）；截断行拒绝（abmr001）；登出强校验 |
| 安全 | 密码禁入 TOML/聊天输出/提交文件；写操作显式确认；最小权限账号 |
| 可审计 | 每响应含查询时间戳（UTC+8）、行数核对、会话登出状态；trace_dir 可选诊断 |
| 可测试 | 单元 + 每功能 e2e 双层测试（tests/ 24 个测试文件）；架构一致性测试 |
| 可维护 | 功能模块化注册（features/ 目录一功能一文件）；Pylance 零诊断 |

## 8. 成功指标

- **替代率**：高频 ERP 查询场景（订单导出、BOM、物料三件套）agent 调用覆盖率 100%（已基本达成，每日 10:00 自动链路稳定运行）。
- **契约可信度**：调用方可机器判定结果（`ok && complete && 行数一致 && logout_verified`）的比例 ≥ 99%；已知例外（如 aimq102 多仓多行 exit 9 但数据可信）有文档化口径。
- **部署成本**：新机器从 clone 到全局可用 ≤ 5 分钟（uv tool install + skill 同步）。
- **写操作零事故**：asfi301 无重复提交、无错部门工单。

## 9. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| ERP 协议/画面变更导致功能失效 | 高 | 契约版本化 + e2e 测试快速定位；响应含完整会话证据便于人工核 |
| 客户端身份绑定（hostname/工作站） | 中 | 文档化配置优先级；hostname 显式可配；已知坑记入技能 |
| 写操作误用 | 高 | confirm_write 强制门 + 禁自动重试 + 部门守卫 |
| 凭据泄漏 | 高 | 密码仅环境变量/请求注入；禁入 TOML/输出/提交 |
| 结果部分返回误判为空 | 中 | `data:null ≠ 无数据` 原则写入技能与本文档 §4.4 |
